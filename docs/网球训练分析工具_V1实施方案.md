# 网球训练分析工具 V1：实施与验收任务书

版本：1.0 · 日期：2026-09-11 · 目标设备：MacBook Air M2（2022），16GB 统一内存

交付对象：负责实现、调试、验证和交付的开发 Agent。

## 1. 交付目标与明确决策

开发一个本机运行的网球训练视频分析工具，包含真实可用的前端。用户可以导入单人对墙练球视频，设置分析区域，执行本地小模型推理，在前端查看骨架、球轨迹、击球事件、正反手及墙面击中点，并逐帧检查、修正、调参比较和导出结果。

首版采用现成预训练权重，不训练、不微调、不依赖云端模型 API。所有视频处理、推理和结果存储均在本机进行。首次安装依赖及下载官方权重需要网络；准备完成后应能断网处理已导入视频。

关键决策：

- 产品形态：React 网页前端 + Python 本地后端，浏览器打开 localhost 使用。
- 运行方式：上传后异步离线分析，单个分析 worker；首版不承诺实时 60fps。
- 支持场景：固定机位、单人、单个活动网球、对墙练习；先分析选中的 10–60 秒片段，跑通后支持最多 5 分钟。
- 核心模型：MediaPipe Pose Full + YOLO11n 通用 COCO 权重；YOLO11s 为可选对照，默认不下载多套模型。
- 模型使用：优先验证 YOLO 的 MPS 后端；失败时明确记录并回退 CPU。MediaPipe 首版按实际 Python 运行时支持选择，允许使用 CPU，不假设两者共享 MPS。
- 球速：首版交付图像平面速度，单位明确为 px/s；真实 km/h 不作为 V1 必交指标。
- Agent 功能：首版用结构化规则生成训练摘要；本地大语言模型、语音教练和训练计划闭环均不进入必交范围。
- 成功标准：真实视频能完整跑通，结果可解释、可复核、可纠错；算法效果单独实测，不用演示数据代替效果证明。

不要将“前端做出来”“模型加载成功”“API 返回 200”当作完成。必须从浏览器导入视频，完成一次真实推理、检查结果、修改事件、重载恢复，并导出可播放文件。

## 2. 原始参考与证据边界

参考笔记：https://xhslink.cn/o/CPX9tssjWi

前序已打开原始小红书笔记并查看约 23 秒视频的多个阶段。画面展示：对墙练球、人体骨架、球轨迹、墙上编号点，以及 strokes、forehand/backhand、shot speed、speed history、shot placement 面板。笔记文字提到 Astra、Python OpenCV、Roboflow。

尚未核实：作者源码、是否实时、是否全自动、有无人工作业、模型版本、实际测速标定、指标准确率。不能将这些未知项当作技术需求依据。

此前对话中的“损失 30%–70%”“某项准确率 90%”“处理时长为视频 2–5 倍”“300–800 帧足以提升”等数字均未经过该场景实测，也没有可直接外推的对照实验，不能作为本项目性能结论或交付承诺。本文中的阈值是产品目标或初始调参值，必须由实验报告补充真实结果。

参考笔记的视频已叠加轨迹和文字，不宜作为原始球检测的准确率基准：叠加的圆圈、线条会改变视觉输入。尽量使用用户自己拍摄、未加工的原视频。

## 4. 使用流程及前端设计

### 4.1 页面与路由

1. `/` 项目页：导入视频、任务列表、状态、缩略图、时长、最近 run、复核进度、打开分析。
2. `/projects/:projectId/setup` 设置页：预览视频，选分析片段，设置持拍手、搜索 ROI、墙面区域/标定、目标区域、推理配置。
3. `/projects/:projectId/runs/:runId` 工作台：视频、图层、时间线、事件、调试数据、复核与摘要。
4. `/projects/:projectId/compare?left=...&right=...` 对比页：同步播放两个 run、事件变化及性能差异。
5. `/settings` 环境页：模型文件、版本与校验、MPS/CPU 探测、FFmpeg、磁盘位置、模型下载进度。

### 4.2 工作台布局

```text
┌ 项目 / Run / 实际设备 / 状态 ── 复核模式 ── 导出 ┐
│ 视频与 Canvas 叠加（约 70%） │ 当前事件 / 调试详情 │
│ 骨架 / 球 / 候选框 / 轨迹    │ 自动结论、来源、分数 │
│ 墙面点 / ROI / 目标区域      │ 接受 / 改正 / 排除  │
├ 播放、±1 帧、±1 秒、倍速、时间码 ────────────────┤
│ 时间线：击球 / 撞墙 / 丢球 / 人工点 / 未分析区域 │
├ 次数、正反手、待复核数、检测覆盖率、px/s ────────┤
│ 事件列表 / 墙面分布 / 参数 / 性能 / 验证报告     │
└────────────────────────────────────────────────┘
```

建议深色视频画布、清晰中文控件、常规表单配色。优先保证视频面积和坐标交互，不投入复杂动效。支持 1280×800 以上桌面窗口；较窄时右侧改为抽屉，避免遮挡视频。

### 4.3 播放、逐帧与坐标

- 倍速：0.25×、0.5×、1×、2×；空格播放暂停，左右键逐帧，Shift+左右键跳 1 秒，表单输入时不触发快捷键。
- 视频播放使用 `requestVideoFrameCallback`（能力检测后使用）；按实际 mediaTime 匹配后端帧 PTS。不要仅依靠 `timeupdate` 或 React 状态刷新驱动高频叠加。
- 精确逐帧模式：暂停视频，调用后端指定帧接口显示静态帧及该帧结果，明确帧号；恢复播放后切回 video。浏览器 seek 无法保证帧精度时不伪称精确。
- 所有模型结果回映到“旋转修正后的分析图像”坐标系。源尺寸、代理尺寸、letterbox padding、ROI 偏移、CSS 缩放及 devicePixelRatio 都要有明确变换。
- 页面缩放、黑边、窗口调整、旋转视频后，点击位置与图层仍要一致。
- 时间轴用源视频时间，分析片段例如 30–60 秒仍显示源时间 30–60 秒；导出片段从 0 开始，同时保留源时间映射。
- 未分析时间段标灰，绝不延用上一帧识别结果冒充当前识别。

### 4.4 调试与复核细节

每帧侧栏展示：源 PTS、帧号、模型耗时、球候选类别及原始 confidence、选中候选、拒绝原因、当前轨迹状态、姿态 visibility、事件依据。

图层必须可独立开关：骨架、球候选、选中球、轨迹、球拍框、墙面点、ROI、低置信标记。观测点用实线，预测/插值用虚线，人工点用单独颜色和图例。

每个事件展示前后片段、类型、正反手/unknown、自动来源、复核状态。支持修改时间、类别、点坐标，添加漏掉事件，排除误检，撤销最近一次修改。修改后更新“已复核”视图，原始自动视图保持不变。刷新页面后修改不丢失。

球点修正产生 correction revision；只有用户点击“基于修正重新计算”才创建派生 run，不在后台静默改变下游事件。派生 run 标记 `assisted`，不能混入纯自动模型评分。

### 4.5 A/B 对比

- 两个 run 必须属于同一视频；比较共同时间区间，区间不重叠时给出明确提示。
- 支持同步时间、暂停逐帧、左右或切换查看；识别断点用不同颜色标出。
- 展示参数变化、检测覆盖、事件新增/消失、正反手变化、处理耗时、内存及失败信息。
- 已有独立人工真值时才比较准确率；没有真值只写“结果变化”，不自动判定哪个更准。

## 5. 技术架构与本地部署

### 5.1 默认技术栈

| 层 | 选型 | 用途 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 本地调试工作台 |
| UI/绘图 | 普通组件库或轻量 CSS；Canvas 2D；ECharts | 表单、视频图层、分布与趋势 |
| API | FastAPI + Pydantic | 上传、任务、结果、复核接口 |
| 推理 | Ultralytics YOLO11n；MediaPipe Tasks Pose Full | 检测与姿态 |
| 视频 | FFmpeg/ffprobe + PyAV；OpenCV | 转码、带 PTS 解码、图像处理 |
| 存储 | SQLite WAL + 文件目录 | 元信息、run、事件、修改记录、帧结果 |
| 测试 | pytest；前端测试工具；浏览器端到端测试 | 几何、状态、API、交互及闭环 |

Python 以 3.11 为兼容性起点，前端使用当前支持的 Node LTS；实际版本经 Apple Silicon 安装及推理 smoke test 后锁定，提交 lockfile。若现有项目已有同类栈，优先复用并说明映射，不为套用本文重建已有系统。

### 5.2 进程与任务

```text
浏览器 → FastAPI → SQLite 持久任务队列 → 单个 worker 子进程
                  ↓                           ↓
             项目/复核数据             帧结果 / 事件 / 导出
```

- 本机默认绑定 `127.0.0.1`，开发前端代理 `/api`，正式本地模式由后端托管构建后的静态前端。
- 不用 FastAPI 请求线程承载长时间推理；用独立 worker 进程处理。无需引入 Redis/Celery。
- 分析与视频导出共用单个重任务执行槽，避免同时抢占 M2 统一内存；轻量读接口仍可响应。
- 队列 claim 必须原子化。后端重启或 worker 崩溃后，将失去心跳的 running 任务标记为 interrupted，而非永久 running。
- 取消：逐帧/逐批检查取消标记；转码时管理 FFmpeg 子进程；停止后释放模型/文件句柄。必要时有超时终止兜底。
- 任务状态：`queued → running → succeeded / failed / cancelled / interrupted`。阶段另设 `probing / preparing / inference / events / exporting`。
- 导入资产准备状态与分析任务分开。缺模型、错误路径、解码失败、MPS 错误必须返回可操作原因。
- MPS 推理失败后，首版可将该次尝试作废并用 CPU 重跑片段；记录 attempts、失败原因及实际设备，不拼接两次产生重复帧。
- 默认前端每 1 秒轮询任务状态；首版不要求 WebSocket。未知阶段时长时显示阶段和帧进度，不伪造 ETA。

### 5.4 本机资源及输入限制

- 默认 batch=1、单分析任务；模型驻留、帧流式读取、结果分块落盘。禁止把整个视频所有 RGB 帧留在内存。
- 默认上传上限 2GB，分析片段上限 300 秒；前端推荐先跑 10–60 秒。更大输入提示裁剪，不静默截断。
- 接受 MP4/MOV 容器，实际由 ffprobe 检查视频轨、编码、尺寸、时长；不能只信文件扩展名。
- 支持常见 H.264/HEVC 输入，生成 H.264、yuv420p、faststart 代理供浏览器播放；原片保留不改写。
- 推理从原始解码帧或明确记录的分析帧读取，不能默认用低码率预览代理作为模型输入。
- 保留 VFR 时间戳、旋转元信息处理结果。若必须转 CFR，保存映射，并记录新增/丢弃/复制帧策略。
- 目标：整个应用峰值内存尽量低于 8GB，前端避免加载整段逐帧 JSON；此为待测预算，不是预先保证。
- 启动 doctor 报告芯片架构、Python、FFmpeg、模型文件、MPS 可用性、磁盘空间。不要假设开发机器就是目标 M2。

## 6. 无训练视觉流水线

### 6.1 输入与拍摄指引

首次界面提示：手机固定、尽量横拍、光线充足、完整看到人体与墙面、保留原音，优先 1080p/60fps。这只是建议，30fps 输入仍允许处理并标明时间精度限制。

用户选择持拍手 `right / left / unknown`；左右按人物解剖学方向，不是屏幕左右。默认 unknown，不自动把左手球员当右手。镜像视频提供开关并保存配置。

ROI 可以手动设置，默认全图。墙面区域与球搜索区域是不同对象；球会离开墙面在空中运动，不能将球搜索局限到墙上。

### 6.2 人体姿态与球拍

- MediaPipe Full，单人，VIDEO 模式，使用严格递增的真实毫秒时间戳。新 run、新时间段或倒序检查时创建合适的新状态，避免复用时序缓存污染。
- 默认每约 66ms 处理一次姿态，按时间而不是每 N 帧定死；允许关键挥拍区间提高频率。
- 低 visibility 关节不参与可靠分类。骨架短间隔插值仅用于显示，并标记来源；不要跨长遮挡连接身体。
- YOLO 根据模型 names 映射查找 `sports ball`、`tennis racket`、`person`，不要只写死类别整数。COCO 通用类别包含球和球拍，但不直接输出正反手。
- 球拍框作为辅助证据，球拍不可见不必让整条流水线失败。

### 6.3 球检测和追踪

先实现可解释基线，再加优化。首个基线：YOLO11n 对搜索区域逐帧检测，候选映射回原图；卡尔曼滤波预测 + 候选关联。只允许一条活动球轨迹。

候选选择综合原始置信度、距预测点距离、尺寸范围、运动连续性；阈值统一配置。拒绝候选必须能在调试视图查看原因。模型 confidence 与组合 tracking score 分别保存，不称作“准确率”。

轨迹状态：`uninitialized → tracked → predicted → lost → reacquiring`。存在多个接近候选时允许 ambiguous，不能任意切球后装作连续。

- 默认只允许约 80ms 的短缺口预测，具体需调试；用毫秒而非固定帧数。
- 遮挡过长后轨迹断开，重新捕获新段。预测点不得独自触发击球/撞墙等新事件。
- 事件附近方向变化快，避免强平滑抹掉撞击；保存 raw 点和 filtered 点供比较。
- 局部检测为优化模式：围绕预测点裁剪，坐标正确回映；每约 300ms 全 ROI 重捕获，lost 时立即重捕获。
- 颜色/帧差候选只作为可关闭的辅助模块，不替代模型结果；初始默认关闭，避免将涂鸦或反光当球。
- 不要求每帧都检测成功；要求系统明确区分观测、预测和未知，并报告覆盖率。

### 6.4 事件提取

采用两阶段离线处理：先推理得到时间序列，再提取事件。这样调事件参数不必重新跑检测。

击球候选：球轨迹在球拍/持拍手附近，有可观测方向或速度变化，且有挥拍证据。各证据分别保存；仅有挥拍但看不到球时可以输出 `swing_candidate`，不直接计入确认击球。

撞墙候选：墙面区域附近的轨迹反转、接触前后可见轨迹及可选声音；单纯进入墙面投影范围不足以证明撞墙。证据不足时输出 `wall_contact_candidate` 供复核，不产生伪精确墙点。

落地反弹：首版可作为排除击球的候选类型；不要因为反向就累加击球数。若无法可靠判断，保留 ambiguous。

初始状态序列为 `unknown → player_hit → outgoing → wall_contact → returning`；落地、漏球、暂停时允许转 unknown，不强制每球完整闭环。去重窗口初值 250ms，可调，防止一个动作多计；不要吞掉时间上接近但有独立证据的事件。

正反手：结合持拍手、身体局部坐标、持拍腕相对躯干的位置和击球前后动作判定。身体朝向不清、交叉遮挡、双手反手证据不足时用 unknown。不能用“球在屏幕左边即反手”。

V1 不训练动作分类器；实现规则及可观察证据，并支持人工改正。

### 6.5 墙面标定与指标

墙面设置包含：四点顺序、可选实际宽高、目标多边形。前端校验自交/共线/退化，服务端再校验；四点必须对应墙面上已知矩形或有定义的坐标点。

- 未标定：仅画图像坐标散点，标签“图像击中位置”。
- 有四点但无尺寸：显示归一化墙面位置、目标区命中情况。
- 有可靠尺寸：可显示墙面平面内距离及分散程度。
- 标定仅适用于墙面接触点，不能将空中球逐帧投影到墙面后当作真实运动距离。
- 撞墙时间/位置不确定时，保留误差说明或候选，不把最近一帧的墙面投影自动当真值。

首版速度为观测轨迹在原始分析图像上的局部 px/s，使用真实 Δt 和短窗口稳健计算；不跨击球、撞墙、长缺口估计，不用预测点生成漂亮峰值。前端写明“像素速度；仅相同机位和画面条件下参考”，缺数据用空值并给原因。

真实速度字段保留 `speed_kmh: null`、`unavailable_reason`。即使用户输入墙宽，也不能自动解锁 km/h。

摘要只使用支持该结论的数据。例如“已复核 18 次击球，其中正手 10、反手 6、未分类 2”。候选数、自动数、复核数分开；未知不从分母中悄悄消失。

## 7. 数据契约、结果来源与接口

### 7.1 主要实体

- `Project`：id、原始文件 hash、文件名、尺寸、旋转、时长、时间基、代理状态。
- `Calibration`：revision、坐标系、四点、可选尺寸、目标区域、有效性。
- `Run`：id、project_id、parent_run_id、自动/辅助模式、时间区间、配置、模型 hash、代码版本、标定 revision、状态、性能。
- `FrameObservation`：frame_index、source_pts_ms、球候选、观测/预测点、轨迹 id、姿态、耗时。
- `Event`：id、run_id、源时间、类型、分类、坐标、证据、分数、候选状态。
- `Correction`：id、run_id、event/point 引用、操作、旧值/新值、revision、时间。
- `GroundTruthSet`：独立标注集、视频和区间、标签定义、版本。
- `Export`：输入 run、correction revision、图层配置、格式、状态、产物 hash。

示例事件（结构示意，不是实测数据）：

```json
{
  "id": "event_uuid",
  "run_id": "run_uuid",
  "source_time_ms": 12340,
  "frame_index": 740,
  "type": "player_hit",
  "stroke_type": "unknown",
  "origin": "automatic",
  "review_status": "unreviewed",
  "heuristic_score": 0.62,
  "evidence": {
    "ball_observed_before": true,
    "ball_observed_after": true,
    "near_racket": true,
    "direction_change": true,
    "handedness_available": false
  },
  "point": {"x": 1012.0, "y": 624.0, "space": "analysis_image_px"},
  "speed_kmh": null,
  "unavailable_reason": "no_validated_3d_measurement"

```

JSON 不输出 NaN/Infinity，缺失用 null + reason。坐标必须显式记录 space。框/点每次 crop、resize 的映射可追溯。

自动结果不可变；人工修改以追加日志形成 materialized reviewed view。独立真值不能直接由这层 reviewed view 默认生成，否则会引入对自动结果的依赖。

### 7.3 缓存和重算边界

- 改模型、输入尺寸、检测 ROI、检测阈值、推理采样、跟踪参数：生成新 run；可复用兼容的上游数据，但不能重用已过滤掉候选的数据来降低置信阈值。
- 只改事件去重阈值、正反手规则：复用不变的观测/轨迹，再算事件。
- 改标定/目标区：复用观测和事件，重新计算墙面映射及指标。
- 改图层颜色/显示：不推理；导出配置独立。
- 使用人工球点：派生 assisted run，独立于 automatic 基线。

## 8. 导出与前端结果一致性

MP4 包含原始画面叠加及可选底部面板，尽量保留原音；输出 H.264/yuv420p，检查浏览器实际可播。速度面板必须写 px/s，不能照搬原视频 km/h 文案。

CSV 每行一个事件，包含源时间、类型、分类、来源、复核状态、坐标与单位。JSON 包含配置、模型和代码版本、标定、事件、correction revision、摘要、性能；大规模逐帧结果可另附分块文件和 manifest。

导出默认让用户选择“自动结果”或“已复核结果”。每次导出冻结对应 revision，不随之后的修改变化；文件名区分 auto/reviewed/assisted。

前端与后端渲染共享坐标规范和结果 schema。抽查开头、中段、末尾同一 PTS 的位置一致；导出时长、音画偏移和事件位置需要核对。未确认墙点和 unknown 分类不能在导出时被悄悄删除或改成确定结论。

## 9. 验证设计与验收门槛

### 9.1 三种证据分别报告

1. 工程闭环：功能是否真的工作。
2. 目标设备性能：该 M2/16GB 上的耗时、峰值资源、持续运行表现。
3. 算法效果：对独立人工真值的自动结果评分。

三者分别给 pass/fail/not_measured。不能因工程通过就说识别可靠；也不能因准确率不足就只交静态页面。

### 9.2 输入样本

- 至少 3 段不同时间拍摄的未标注原视频，每段 20–60 秒，合计目标不少于 50 次击球；覆盖正反手、球短暂遮挡及背景差异。
- 设置调参集与独立留出验证集，按视频/拍摄段分开，不能将相邻帧随机分到两组声称泛化验证。
- 另备旋转 MOV、VFR、无音轨、损坏文件、无人/无球片段用于工程测试。
- 当前任务没有用户原始视频文件。开发 Agent 应先完成应用与测试基础设施；可使用来源明确、允许下载使用的未加工公开样本。没有合适真实素材时，使用清楚标记的合成测试资产验证接口、坐标和导出，报告真实算法验收 pending，不冒充已完成。
- 不自动从相册或私人目录寻找视频；也不把小红书叠加视频当独立真值集。

### 9.3 独立人工标注工作流

在前端提供“独立标注”模式，默认隐藏自动事件、预测轨迹和统计。用户逐帧标注击球时间、正反手/unknown、可确认撞墙点；球位置使用固定规则抽样（例如每 100ms，事件附近加密）。标注点必须能导出、保存、重载和修改版本。

标注保存并锁定版本后再显示自动结果进行匹配。对遮挡、模糊和无法确定的点设 unobservable，明确是否计入分母。独立真值与日常“纠正模型结果”的用途不同。

### 9.4 评分规则

| 项目 | 定义 |
|---|---|
| 击球事件 | 同视频同区间，一对一匹配，时间容差默认 ±100ms；最大匹配数优先，再最小化时间差；多余预测计 FP，漏掉真值计 FN |
| Precision / Recall / F1 | 分别报告 TP、FP、FN 及分母；无预测/无真值的情况定义清楚 |
| 正反手 | 匹配击球中的混淆矩阵、unknown 数；同时给含漏击球/unknown 的端到端正确分类比例 |
| 球位置 | 仅在标为可见且可定位的人工帧上算召回与定位误差；容差可配置，必须记录原图 px 及对角线归一化值 |
| 轨迹 | 最长断轨时长、观测覆盖、预测占比、错误跳球样例；检测覆盖率本身不是准确率 |
| 墙面点 | 仅比较可确认撞墙事件；用墙面归一化坐标，若有有效尺寸再给 cm；报告事件匹配率与位置误差分布 |
| 性能 | 准备、检测、姿态、跟踪、事件、导出分项耗时；端到端耗时/视频时长；峰值内存；实际设备 |

所有指标分别对 automatic、reviewed、assisted 标记来源，主算法评分只针对未修正 automatic run。输出失败事件列表，点击能跳转原视频证据。

### 9.5 V1 验收清单

工程必过：

- [ ] 一条启动命令启动前后端，README 写明首次准备步骤。
- [ ] 模型缺失时界面可见，下载或本地导入官方权重后恢复；不显示假分析结果。
- [ ] 导入真实视频后，可选片段并得到模型实际产生的检测/姿态结果。
- [ ] 刷新浏览器保留 run 和任务状态；取消后可再次分析；崩溃任务可识别。
- [ ] 播放、精确帧、图层、事件跳转正常；图层坐标误差不超过显示映射/像素取整容差。
- [ ] 人工增删改、撤销、刷新恢复正常，自动结果不变。
- [ ] 新参数产生新 run，可 A/B 对比；旧配置与旧结果完整保留。
- [ ] MP4 可播放、时间对齐；JSON/CSV 与冻结的 UI 视图一致。
- [ ] 正常使用不请求远程推理；模型准备完成后的断网 smoke test 通过。
- [ ] 错误文件/无球/低置信/不支持的配置均有明确状态，无静默虚构。

算法目标（不是承诺，也不是允许人工修正后凑数）：

- 干净固定机位留出样本，击球事件 precision、recall 均以 ≥0.85 为第一轮目标，同时报告 F1。
- 已匹配且人工可分类的事件，正反手正确率目标 ≥0.85，并单列 unknown 占比与端到端结果。
- 墙面点和球定位先建立基线，不预设未经验证的厘米级指标。若不能可靠自动定位，保留候选+人工确认，明确功能成熟度。
- 不达目标时做一轮有记录的无训练优化对照（small、ROI、分辨率、规则），保留最佳与基线；仍不足则交付可用调试工具及失败分析，标明“算法目标未达”，不得擅自开展训练或声称通过。

性能目标：目标设备常规操作可响应；取消请求 2 秒内被确认、重任务争取 5 秒内停止；应用峰值内存预算 8GB。使用同一段 60 秒视频做至少一次冷启动和两次暖运行，记录实际资源与环境。是否接近实时由结果决定；没有在 M2 上跑就写“目标设备未实测”。

### 9.6 有价值的自动测试

- 坐标：ROI+letterbox+旋转+显示映射的已知点往返误差；墙面四点退化校验。
- 时间：VFR/非零片段起点/导出起点的 PTS 对齐。
- 追踪：短缺口预测、长缺口断轨、多个候选不乱跳、方向反转不被过度平滑抹掉。
- 事件：击球与墙反弹不重复计数，unknown 保留，匹配算法一对一且容差边界正确。
- 数据：自动结果不可变、correction undo、revision 冲突、派生缓存失效。
- 任务：取消、worker 崩溃、重启恢复、CPU fallback 不重复写帧。
- E2E：导入→设置→真实分析→定位事件→修正→刷新→对比→导出。

CI 可以使用小型确定性 fixture 和模型适配器 stub 验证工程逻辑，但至少保留一次真实权重、本地视频的单独 smoke test。stub 结果不可用于模型准确率或真实推理交付证明。

- 至少一次真实推理的 UI 截图、可播放导出及对应 JSON/CSV；若真实素材缺失，明确 pending，并仅提供标记为 synthetic 的工程演示。
- `reports/known-limitations.md`：零训练局限、未知场景、速度单位、哪些是候选、尚未达标项目。
- 实施 checklist，逐项附证据位置，便于下一位 Agent 继续。

完成后的答复应包括：启动命令/地址、实现范围、验证结果、产物路径、已知不足及最值得继续的一项改进。不要只给截图或“已搭好框架”。
