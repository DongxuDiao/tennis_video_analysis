# Tennis Lab：本地网球训练视频分析

面向苹果生态的本地工具。导入 MP4/MOV 后，使用 YOLO11n 与 MediaPipe Pose 分析目标人物、球轨迹和事件候选；网页工作台支持逐帧检查、图层开关、参数调优 A/B、独立人工标注与评估、人工复核及 MP4/CSV/JSON 导出。全部推理在本机离线完成。

## 已实现

- **任务与存储**：FastAPI + SQLite 持久队列 + 独立单 worker；原子领取、心跳、取消（≤250ms 检查一次）、崩溃标记 interrupted。
- **导入**：原视频探测（含 HEVC 10bit、旋转元数据）、浏览器 H.264 代理、缩略图；推理读原片。
- **人物身份关联（单目标）**：设置页在首个人物帧显示人物框，点击选择目标（默认最大框）；帧间用 IoU+中心距离+尺寸+运动预测关联；丢失显示“目标丢失”，不切换到其他人；长丢失后仅在唯一合理候选时低置信重锁。人物轨迹优先用姿态髋部中心并标注来源。
- **三种检测模式**：`full_frame` 整图基线 / `tiled` 分块整图 / `tiled_local` 分块发现+局部高分辨率跟踪（默认）。分块数量、重叠、输入尺寸、搜索频率均可配置；调参生成新 run，A/B 对比。
- **球追踪**：综合评分关联（置信度+距离+尺寸+运动一致性+静止误检惩罚）；观测实线与预测虚线严格分开；断轨显示“丢失”；预测点不计入事件与召回。
- **动作判断**：连续姿态挥拍时间窗（与球检测解耦）；击球候选=挥拍窗内球观测+空间接近或轨迹变化；正反手用连续窗证据判定，不足时输出 unknown，可人工改正。
- **工作台**：requestVideoFrameCallback 同步、后端精确帧模式、观测/预测时间线分带、每帧证据（候选+拒绝原因+评分明细、姿态来源、搜索窗）、事件跳转。
- **独立标注与评估**：标注模式隐藏自动结果，点击标球/不可辨认/击球时刻，保存锁定真值集；评估输出 P/R/F1、TP/FP/FN 与分母、球召回与定位误差、失败样例可回跳。
- **复核与导出**：自动结果不可变；人工确认/改正/排除按 revision 追加、可撤销；导出冻结 revision 的 MP4（px/s 标注）/CSV/JSON。

速度只显示图像平面的 px/s；km/h 恒为不可用并给出原因。

## 实测摘录（详见 reports/）

- 切片5（1080p59，22s）：球观测覆盖 4.1%（基线整图）→ **72.6%**（分块+局部），6.6× 实时，703MB。
- 切片2（1080p59，48.7s）：球极小（中位 10px）→ 3×2 分块覆盖 17.2%、人物目标覆盖 92%；4×3 分块在 3×2 完全无候选的时段实测覆盖 78%（分辨率瓶颈验证）。
- 击球 P/R 等算法指标：**not_measured**（完整人工真值待标注，不以覆盖率冒充召回）。

## 首次准备

需要 Python 3.11/3.12、Node.js 及网络（仅首次装依赖/下模型）：

```bash
cd backend
uv sync --group dev
cd ../frontend
npm install
```

模型可在前端“环境”页检查并下载（YOLO11n 官方权重 + MediaPipe Pose Full，manifest 带 SHA256 与许可记录）。完成后日常推理完全离线。

## 启动

```bash
./scripts/dev.sh        # 构建前端 + 启动 API(:8765) 与 worker
```

浏览器打开 <http://127.0.0.1:8765>。开发热更新另开 `cd frontend && npm run dev`。环境诊断：`./scripts/doctor.sh`。

## 推荐用法

1. 导入 → 设置页选目标人物与检测模式（小球远机位建议 4×3 分块）→ 先分析 10–20 秒短段验证效果。
2. 工作台“参数”页调参：改检测/输入/搜索策略会重跑推理生成新 run；仅改事件参数可“复用检测重算”。
3. 两个 run 在“对比”页同步查看差异，再决定是否全片分析。
4. 需要指标时进入“独立标注”完成真值集（每 ~100ms 一点、事件附近加密），再评估。

## 模型连接（可选增强复核）

主页右上角“模型连接”是唯一设置入口。默认未启用：所有分析完全本地。

- **GLM 普通 API（独立计费）**：粘贴 Key → “测试并保存”（发送一张合成图，可能消耗少量额度）→ 启用增强复核。Key 存 macOS Keychain，数据库/日志/前端不保存。
- **GLM Coding Plan（套餐）**：资格待确认，界面不可启用（附官方文档链接）；确认前不向套餐端点发送任何请求。
- 启用后，新分析任务会在本地分析完成后，把**异常窗口的关键帧**（疑似换人/归属冲突/触球附近断轨等，≤6 窗 × ≤8 帧 × ≤12 次请求）发送给智谱复核；模型提议必须通过本地证据验证才生效，全部审计落盘（`enhancement_summary.json`）。原视频不整段上传；关闭后新任务只用本地。
- 结果页显示来源（“本地分析 · GLM 复核 N 段”）；任何云端失败都保留本地结果。

技术设计见 `docs/GLM接入验证记录.md`；实现位于 `backend/app/{model_connections,model_providers,skill_runtime,enhancement}/`。skill 快照（`user_skills.zip`，SHA256 钉住）安全解压到 `backend/app/skill_runtime/vendor/`，只作为数据消费、从不执行。

## 当前限制（摘）

- GLM 增强复核尚未用真实 Key 联调（真实视觉探测/账单核对待用户启用后执行）；套餐资格未确认，保持“适配待激活”。
- 零训练通用权重：小球（<10px）与运动模糊漏检明显；专用网球检测器接入未启动（§五D 条件流程已定义）。
- 击球/正反手准确率未实测（真值标注未完成）；conf 与规则分数不是准确率。
- 分析为离线单任务（3.3–6.6× 实时），非实时；取消/崩溃恢复路径存在但未做系统压力测试。
- 墙面四点交互编辑仍待实现（后端标定与撞墙候选接口已有）。

完整需求见 [V1 实施方案](docs/网球训练分析工具_V1实施方案.md) 与 [开发 Agent 启动任务](docs/开发Agent启动任务.md)。

## Docker 部署（保留现有数据）

```sh
./scripts/docker.sh up -d --build
./scripts/docker.sh ps
```

访问 http://127.0.0.1:8765 。数据保留在当前 `data/`。不要与原生服务同时使用同一数据库。Apple Silicon 上当前镜像为 ARM64 CPU 模式；默认 YOLO + TrackNet 自动分析可用，但容器不包含没有 Linux ARM64 wheel 的 MediaPipe，且速度显著慢于原生 MPS。GLM Keychain 凭据需在容器页面重新配置。详见 [Docker 部署说明](docs/Docker部署.md)。
