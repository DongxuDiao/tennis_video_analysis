# 自动分析与可选逐拍修正（本地版）

默认操作：打开项目卡片 →「开始全自动分析」→ 直接查看标注视频与报告。无需人工标注。下方原有四步流程仅用于可选精细标定。

来源：用户提供的 sports-video-motion-analysis skill。原脚本已适配到 backend/app/expert_engine；该工作流需要人工确认场地线、球点与触球时间，不是纯自动识别的准确率升级。

## 使用

打开项目卡片下的「逐拍精细分析」。

1. 准备素材：60秒内固定机位、恒定帧率视频；提取正确方向的原尺寸帧、YOLO11m姿态、音频冲击及球候选。当前 Mac 使用 MPS，其他设备回退CPU。
2. 标记场地：每条线点击两个端点，至少4条；建议额外标记远端底线作为尺度约束。点击拟合后选择新版本，检查标定叠加和日志。仅残差低不能保证线身份正确。
3. 逐拍复核：指定触球帧、正反手；逐帧点击来球/出球中心。来球至少4点，或提供已知世界坐标触球点；出球至少3点。帧号从0开始，坐标为原尺寸像素。
4. 确认机位稳定、尺度依据和复核状态后拟合；选择完成的新版本查看报告，再导出中文视频。

可从JSON导入skill的shots_input.json；ident.json的内容放入ident字段。完整配置可从input.json下载。编辑草稿按项目和版本保存在当前浏览器；换浏览器前请保存JSON。每个后台步骤产生独立版本并支持取消。

## 测量边界

速度是物理模型拟合，不是雷达实测。条件区间不含标定、触球时间、旋转误差。落点为旋转假设下外推；旋转场景不一致或置信不足不作明确判定。姿态指标属于二维投影代理，遮挡时不可解释为真实三维转体角度。

尚未取得参考输出的原始人工标定/球点，因此没有验证同一输入下重现参考报告数值。示例视频的人体覆盖率不代表关键点准确率，自动黄色候选也不等于真实球。

## 运行与验证

使用 scripts/dev.sh 构建并启动本地服务。依赖由backend/uv.lock锁定；权重data/models/yolo11m-pose.pt，来自Ultralytics官方assets v8.3.0，首次需要自行放置。

2026-09-15：35秒真实视频素材准备完成（1050帧，约280秒）；34个后端测试通过，前端构建通过；完成30帧中文渲染冒烟测试（测试标定，不可作该视频球速证据）。原项目常规分析入口保留。

## 全自动默认入口（2026-09-15 更新）

点击项目卡片进入「自动网球分析」，点击「开始全自动分析」即可。持拍手默认为自动判断，可选填右手/左手提高正反手规则的解释性。无需场地标定、逐帧点球或勾选复核。

后台自动完成：素材及姿态准备 → TrackNet逐帧推理与颜色/运动候选融合 → 时序轨迹过滤 → 挥拍/声音/球接近手腕的证据组合 → 中文报告和带原声视频。已有成功准备版本可复用素材，产物仍保存为新版本。人工修正入口折叠保留。

自动输出的正反手是姿态规则推断，而非经过该场景训练的动作分类器。持拍手不明确时留空；人体缺失时不凭声音生成击球。轨迹至少需要4个观测点和运动证据，最多填补约80ms短缺口，长缺口保持断轨。插值与真实模型观测分开记录。

自动模式不使用虚构相机参数，不输出三维球速/落点。自动模型仍可能识别到相邻场地的球或人体附件，需结合导出视频检查；覆盖率仅描述输出数量，不是精确率/召回率。

产物：auto_candidates.json（候选来源），auto_tracks.json（观测/插值与段ID），auto_summary.json（覆盖与模型标识），shots.json（事件证据），report.md，annotated.mp4。input.json保存可选修正的逐拍建议，reviewed始终为false。

模型：环境页可安装YOLO11m-pose；TrackNet使用既有data/models/tracknet_tennis.pt，来源与兼容格式见TrackNet.md。没有兼容权重会明确报错，不伪装成模型已运行。

### 本次真实视频验证

样例：20260914-172136.552-1.mov，35秒，1050帧。自动结果7个击球候选，疑似正手4、疑似反手2、未确认1。保留226帧球观测与14帧短缺口插值（观测覆盖21.5%，不是识别准确率）。人体覆盖100%也不等于所有关节可靠。

首轮宽松关联出现腿部和邻场误检，已加入人体躯干/下肢排除、主球员关联、运动连续性与模型支持检查。声音缺失时需轨迹转向证据，约0.9秒内重复候选合并。此验证只针对一个视频，尚未建立独立标注集的精确率/召回率，不承诺达到参考视频的人工复核精度。

全自动任务可复用同项目、同权重与兼容输入格式的模型候选，但每次重算追踪/事件并生成新版本。首轮完整TrackNet分析加渲染约7分钟（不含素材准备），兼容候选复用更快。模型加载和推理全部在本机。

最终验收：42项后端测试通过，前端构建通过；导出H.264视频与AAC音频均35.0秒，实际解码1050帧。短音频补齐以显式时长为上限，避免截尾或无限补齐；取消任务会清理子进程组。

## 本地自动复核（2026-09-16）

自动分析现在在首次轨迹形成后检查两端有可靠观测的短缺口，最多复核6处、72次帧推理。每段保持固定裁剪区域，重新使用连续帧 TrackNet 推理；坐标映射回原图后，通过置信度、运动差分、端点范围、人体排除及轨迹关联校验。只补充缺失/插值帧，不覆盖首次观测；没有新检测证据就保持缺口。复核失败保留首次结果。

quality_review.json 记录窗口、区域、推理次数、候选/接受/拒绝数，结果页和报告显示复核摘要。原始候选不混入二次候选，避免重复运行累积污染。

真实35秒样例：6处窗口、21次推理、2个提议、1个通过；观测226→227帧。尚无独立真值，不能证明准确率提升。当前仅修补有端点约束的球轨迹，不自动纠正人体关键点或没有可靠端点的长缺口。云端复核未接入、未上传任何视频；需另行确定供应商、结构化接口与授权后再启用。

## 人物与机位质检升级

- 姿态提取保留多人候选，主球员选择加入位置与尺寸连续性约束；遮挡后短期不直接切换到最大人物框。超过30个缺失帧允许重新捕获，因此不等同于具有长期身份保证的多目标跟踪器。
- person_quality.json 分别记录疑似跳变、缺失和肩/髋/双腕可靠覆盖（以总帧数为分母，阈值0.45）。质量检查在轨迹关联及击球事件之前执行。
- 按触球附近的其他人物腕部运动检查归属歧义；歧义事件保留为低置信未确认，局部朝向与全片标签冲突同样降级。此为保守筛查，不是经过评测的双球员事件分类器。
- scene_quality.py 先抽样机位，特征需空间分布充分且残差合格；只接受小平移、旋转和缩放。触发稳定化后逐帧全部匹配成功才替换分析帧，并保留 source_frames 与变换记录；不通过则原画面分析并提示限制。该版本不处理大幅跟拍、视差、镜头切换或一般透视变化。
- 标注视频以稳定化帧为底图，原视频对照仍为原画面。黑边和坐标系变化在页面及报告说明。未加入 BVP 补球或云端上传。
- 旧素材缓存缺少 people/person_quality/scene_quality 时强制重新准备，防止旧单人结果被当成新版多人质检结果。

验证：原35秒视频11个抽样匹配均通过，最大平移约0.12px，不触发稳定化；前120帧真实姿态推理覆盖120/120，疑似跳变0，双腕可靠覆盖86.7%。旧全片双腕可靠覆盖61.1%，与120帧样本不是同一分母，不能用两者证明精度提高。自动测试覆盖换人拒绝、多人挥拍歧义、缺失数据降级、合成机位位移、稳定化原图保留及匹配失败回退。
