# 独立外部分析与自定义 Skill

## 用户流程

主界面“分析方式”选择本地分析或仅外部模型，上传和重新分析都遵循当前选择。
外部模式必须显式选择已启用、已通过视觉测试的连接。连接可用本身不触发网络分析。
模型连接面板可上传 `.md` 或 `.zip` Skill，已有连接也可更换或恢复默认。
默认采用用户 2026-09-18 提供的 `user_skills (1).zip` 中 `sports-video-motion-analysis` 的 SKILL.md 和 8 个参考文档。

## 两条独立执行路径

- 本地：沿用人体姿态、TrackNet、事件检测、标注渲染；不再自动调用 enhancement。
- 外部：已转正的代理视频 → 本机抽帧 → 外部模型视觉分析 → 严格结构校验 → 本机标注视频与 Markdown 报告。
- 外部任务不加载 YOLO/TrackNet、不复用本地识别数据、不运行音频冲击或球场标定。
- 外部请求失败则该任务失败，保留已有结果与本次审计数据，不降级为本地分析。

## 首版能力边界

外部模型通过单张按时间排序的拼图接收每批最多 4 帧；约 4 帧/秒，60 秒视频最多 250 个抽样帧、63 次批请求。
每批只调用一次适配器；Coding Plan 无自动重试，普通 API 保留原适配器对格式异常的一次修复行为。
请求等待期间持续维护心跳并检查取消；正在发送的单次请求不可撤回，最长由 180 秒请求超时约束。
多格拼图内容仍需具体模型实测，单图颜色测试通过不代表人物/小球定位精度已验证。
标注仅显示被分析帧上的人物框和小球估计，不补出连续轨迹、不编造骨架。
抽样击球候选不等于真实总击球数。真实球速、三维落点、真实关节角均不输出。
原 Skill 中依赖本地脚本、人工审定和物理拟合的步骤不在此模式执行，报告明确说明这些限制。
此首版不保证比本地更快：耗时还受模型延迟、抽帧数及 Skill 长度影响。

## Skill 与任务一致性

ZIP 只读取 Markdown，不解压、不执行脚本、不访问文档链接。输入限制 2 MB，解压总量 8 MB，Markdown 总量 240 KB；拒绝路径穿越、符号链接和多个 SKILL.md。
文本与参考文档生成 SHA-256，保存为不可变文档。连接保存 skill_id；排队时冻结连接 id、revision、skill hash。
执行时写入 skill_snapshot.json。连接断开、换 Key 或换 Skill 导致 revision 改变时，旧外部任务停止，需重新分析。
模型只能返回有限 JSON：帧编号、0..1 人物框与球点、候选击球、观察和建议。帧集合、坐标、长度与额外字段均校验，不将模型响应作为工具指令执行。

## 验证

离线测试覆盖 ZIP 约束、默认包、版本固定、独立路由、非法坐标、请求失败不回退、取消、上传鉴权、配置冲突，以及假模型 → 真 MP4 渲染端到端。
未用用户真实视频调用外部服务；真实视觉质量和耗时须在有额度且通过视觉测试的连接上验收。

## 超时修复
默认 Skill 使用经整理的外部视觉执行版，原始 9 份文档完整保留在默认包与任务快照中；不再每批发送全部脚本教程和参考文档。自定义 Skill 保持用户原文。每批 4 帧，最多 4096 输出 tokens，180 秒等待，超时仍不自动重发。请求审计记录输入大小、等待上限和耗时，不保存密钥。

## 输出截断修复
GLM 结构化标注请求显式发送 thinking.type=disabled，减少思考预算挤占最终 JSON。真实首批复测曾返回 HTTP 200、stop_reason=max_tokens、4096 输出 token、只有 thinking 无文本；调整后已取得完整 JSON 并通过帧号/坐标校验。保存停止原因、内容块类型、usage，不保存思考正文。截断、需要工具和空响应分别报错，均不当作有效标注。单批验证不代表整段视频或定位精度已通过验收。

## 球点字段兼容
真实批次出现 ball 为非数组，Pydantic 返回 list_type。输出协议现显式给出可见球点 [x,y] 示例；解析器兼容键恰好为 x/y 的坐标对象，并转换成数组后执行原有范围校验。缺字段、额外单位、字符串、越界值均不猜测修复；不可见球仍须为 null。
